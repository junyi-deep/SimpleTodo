# 专注任务搜索

专注窗口的“关联任务”下拉增加搜索输入，便于在任务较多时快速选择。本次是现有紧凑桌面控件的局部扩展，沿用 [PRODUCT.md](../PRODUCT.md)、[DESIGN.md](../DESIGN.md) 与 `.impeccable/design.json` 已确立的 Quiet Neutral Workstation 视觉系统。

## 使用规则

- 打开“关联任务”后自动聚焦“搜索专注任务”输入框；按任务标题做子串匹配，忽略查询两端空白与字母大小写，支持中文。
- 搜索只筛选已有选项。任务来源仍为专注面板原有的 `s.roots`，保留“自由专注，不关联任务”；不扩大到其他任务范围。
- 输入时方向键上／下移动活动项，Enter 确认；空格正常输入。中文输入法组合期间的 Enter 不会误选任务。
- Esc 关闭并将焦点还给触发器；选择后同样返回触发器。Tab、外部点击或窗口尺寸变化会收起浮层。
- 无匹配时显示“没有匹配的任务”，此时 Enter 不提交，也不改变原有关联任务。
- 每次重新打开都清空查询，并将当前选中项设为活动项、滚动到可见区域；直接按 Enter 保留该项。
- 选中任务写入 `taskID`，点击“开始专注”时由实际 `Focus` API 使用该 ID；自由专注传入空关联。计时、暂停、继续和结束流程沿用原规则。

## 实现边界

`frontend/src/components/CustomSelect.vue` 提供可选的 `searchable` 与 `searchPlaceholder` 参数，当前仅 `frontend/src/components/FocusPanel.vue` 的关联任务启用。普通下拉继续使用原来的交互，年月等长列表仍在展开时定位当前选中项。

可搜索浮层使用顶层 Popover，内部为搜索输入与独立滚动的结果 listbox。输入保留 combobox、活动项与列表关联语义，选中项保留勾号；查询变化后从首个可用结果开始导航。相关样式集中在 `frontend/src/styles/visual-system.css`。

## 视觉对照

| 项目 | 沿用或扩展的规则 |
| --- | --- |
| 色彩 | 复用 `surface`、`text`、`icon`、`muted`、`secondary`、`border-subtle` 与已有浅深主题配对，不增加调色板。 |
| 字体 | 沿用系统字体；搜索、选项和空结果文字为 12px，专注时钟保持现有 72px 层级。 |
| 形状与深度 | 沿用 9px 浮层圆角、5px 选项圆角和 `shadow-popover`；触发器仍为紧凑的 32px 控件。 |
| 搜索布局 | Lucide 搜索图标与左对齐输入共用一行，间距 7px，底部细分隔；透明无框输入沿用既有搜索字段规则。 |
| 长列表 | 搜索头固定在浮层内，结果区最高 260px 并独立滚动；整个可搜索浮层最高 320px，定位时适配可用窗口空间。 |
| 焦点与状态 | 按钮继续使用现有单层 1px 内框，活动选项使用 `secondary`，选中状态以勾号表达。 |

本次未修改全局设计 token、字体或资产，也未重写设计 sidecar。`DESIGN.md` 的 Custom select 段落描述默认非搜索模式；本文件记录这项可选模式的局部差异，不把它提升为所有下拉的默认规则。其他既有界面差异不在本次修复范围内。

## 验证记录

`frontend/e2e/focus-search.spec.ts` 覆盖中文搜索、大小写匹配、组合输入 Enter、空格输入、方向键选择、无匹配保留选择、重新打开清空查询与恢复活动项、长列表选中项可见、自由专注、Esc 焦点恢复、外部点击／尺寸变化关闭，以及实际 `Focus` 关联 ID。

发布回归已通过完整 89 项端到端测试、9 项前端单元测试及 Go 全量测试、vet、race 检查。最后一次活动项恢复修正后，相关 8 项端到端测试、生产构建、macOS 打包与严格签名验证、Windows 构建通过；独立评审结论为可发布，无实质性修复项。

最终原生深色 480×720 窗口复查：输入“本周”后按 Return 选中“整理本周任务”；重新打开后查询为空，无障碍树中的当前活动项仍是该选中任务，再按 Return 保留选择并将焦点还给触发器。浅深主题 400×740 对照截图为 `.impeccable/review/focus-search-light.png` 与 `.impeccable/review/focus-search-dark.png`。
