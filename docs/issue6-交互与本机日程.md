# issue #6：交互与本机日程

对应版本：0.1.9。来源：[issue #6](https://github.com/junyi-deep/SimpleTodo/issues/6)。

## 清单交互

- 已完成父任务新增子任务时，普通原位草稿显示在已完成子任务之前；提交后顺序保持一致。取消草稿不改变父任务状态，提交未完成子任务后按现有聚合规则恢复祖先为未完成。
- 多选支持任意层级任务。批量完成、取消完成、删除作用于选中任务及其后代，未选兄弟任务不受影响。父子同时选中时按祖先去重；批量预览展示实际影响的分支，提交时检查数据版本。
- Esc 退出多选，即使焦点在复选框或搜索框中。
- 每个节点的展开状态保存在 SQLite，跨视图和重启恢复。新节点按设置的默认层级展开；点击“展开层级”按钮按当前配置重置当前清单，调整层级后保存新的展开状态。
- 日计划可拖住选中日期左右滑动，日期条随拖动移动、选中槽位保持固定；释放后平滑对齐。保留日期点击、前后切换和回到今天。
- 月历、周历的星期标题居中对齐日期列。

## 本机日程

入口：设置 → 本地数据 → 本机 Outlook 日程 → 选择本机日历。选择来源后点击“保存并读取日程”。

| 平台 | 读取方式与范围 |
| --- | --- |
| macOS | 通过 EventKit 读取系统日历账户，包括在系统设置中启用的 Outlook／Exchange 日历。仅保存在 Outlook 应用内部、未进入系统日历的日程无法读取。首次选择来源时请求系统日历权限；macOS 要求完整日历权限，但应用仅调用读取接口。 |
| Windows | 通过经典 Outlook 的本机对象模型读取已有配置中每个存储的默认日历。需要安装并配置经典 Outlook；不支持新版 Outlook，也不宣称涵盖所有共享或嵌套日历。 |

应用不通过 ICS 链接、Microsoft Graph 或云端登录读取日程；不解析 Outlook 私有数据库文件。账户的原有同步由系统日历或 Outlook 自行负责。

月／周日历与日期抽屉只读展示日程。点击打开组件详情，显示时间、地点及只读说明；修改应在 Outlook 或系统日历中完成。日程不进入待办计数、批量操作或拖拽逻辑。

进入日历、手动刷新及在日历停留期间每 5 分钟读取当前日期范围。失败显示原因并保留上次本地缓存；可重试或在设置中重新选择来源。“停止显示”清空来源配置和日程缓存，不影响原始日历。

## 数据与升级

所有层级待办仍使用 `tasks` 单表。schema 2 新增：

- `task_expansion`：任务 ID 主键及外键，删除任务时级联清理。
- `local_calendar_config`：单行来源列表与最后成功读取时间。
- `local_calendar_events`：本地只读日程缓存，独立于待办；`idx_local_calendar_range(start_at, end_at, calendar_id)` 支持范围查询。

展开偏好和日程缓存更新不改变任务版本。旧库升级前在 `backups/pre-schema-v2-*.db` 创建保护副本，迁移保留原任务。完整数据库备份包含新增表；任务 JSON／Markdown 导出不包含日程缓存。旧版本不识别 schema 2，不应直接打开升级后的数据库。

## 验证范围

发布前验证：75 项端到端用例、9 项前端单元测试、Go 全量测试与 vet、任务引擎竞态测试全部通过；macOS arm64 打包和 Windows amd64 交叉编译通过。

Go 测试覆盖分支批量操作与去重、版本冲突、展开状态重启恢复、缓存与任务隔离、失败保留缓存、零时长日程、旧库迁移保护备份及备份恢复。前端自动化覆盖原位草稿位置、子任务多选、Esc、展开记忆、日期滑动、月周对齐及只读日程与失败重试。

macOS 使用独立临时数据目录验收了多选、Esc、跨视图折叠记忆、本机日程设置、未授权提示、缓存显示和只读详情。日程内容使用明确标注的测试缓存，未读取用户真实日程。本机未安装 Outlook，真实 Outlook 账户与 Windows 原生读取尚未实机验证；不能用界面夹具或交叉编译代替此项结论。
