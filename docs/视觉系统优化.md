# 视觉系统优化

## 为什么原来的黑白界面显得粗糙

问题主要在视觉权重和组件一致性。界面多个区域使用同样的白色；标题栏、工具栏、任务内容与辅助信息缺少层级。任务组上下边界叠加，分割线比内容更醒目。图标的线宽、按钮尺寸和圆角在多轮功能扩展中逐渐分散，部分表单又沿用了浏览器默认观感。结果是功能都在，但界面像多个独立部件拼在一起。

Linear 的官方设计回顾强调内容优先、导航退后、统一标题与图标、柔化过多分隔。这里参考的是这些工作界面的组织原则，SimpleTodo 的紧凑清单、多级任务、独立窗口与快捷操作继续保留。

参考：[A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh)、[How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)。

## 本次统一的规则

- **表面层次**：内容面使用白色／石墨色，窗口栏和侧栏使用更安静的一层灰，字段与工具区再用轻微底色区分。浅、深主题使用相同的语义变量。
- **文字**：沿用系统字体，统一标题、正文和元信息层级；日期与统计使用等宽数字。任务正文继续紧凑，辅助信息保留可读对比度。
- **图标与按钮**：Lucide 统一线宽，规范按钮尺寸、内边距、圆角、悬停、按下和键盘焦点。标题栏的视图按钮形成一组，窗口操作保留原来的顺序。
- **任务操作颜色**：根据用户选择，默认灰色；悬停或键盘聚焦时显示标签、提醒、编辑、时间与删除的语义色。二次确认删除仍显示绿色对钩。
- **清单**：去除任务组双重分隔，每组只保留一条柔和细线。保留缩进、原位编辑、完成删除线、提醒和标签；新增按钮只在加号附近提供轻微反馈。
- **浮层与表单**：下拉、提醒、标签、任务设置与确认框共享同一圆角和阴影尺度。标题按正文档标题显示，避免输入框把标题包成小按钮；字段焦点使用细线，去掉重黑外框。
- **日历与甘特图**：保留蓝底白字，降低饱和度并确保完成态文字对比度。打开日期抽屉时，左侧日历缩为完整七列，日期上下文仍可见；不把日期遮在抽屉后面。
- **设置、复盘与笔记**：侧栏降低权重，内容标题和表单层次保持一致；报告、统计与 Markdown 使用统一字体、分隔和控件。
- **专注**：以时间数字作为视觉中心，移除重复的装饰时钟图形。保留原有专注与倒计时行为。
- **动效**：按钮按下反馈缩短、幅度减小；保留任务操作滑出、抽屉、排序、输入星星及系统减少动态效果设置。

## 实现与验证

颜色与语义变量位于 `frontend/src/style.css`；统一外观规则位于 `frontend/src/styles/visual-system.css`，由 `main.ts` 在基础布局之后加载。后续视觉调整应维护这套变量和组件规则，避免再按页面叠加不同的局部外观。

使用隔离演示数据库检查了浅／深清单、400px 窄窗口详情、日历与日期抽屉、甘特图、设置、复盘首页、任务报告与笔记、专注视图。新增界面回归还检查图标默认灰色与悬停语义色、横向溢出和未捕获的页面错误。发现并修复自定义下拉在窗口 resize 事件中把 Window 当成 DOM Node 的错误。

最终验证：84 项端到端回归、9 项前端单元测试、类型检查及前端生产构建通过。独立视觉复核提出的完成态文字对比度和键盘焦点可见性问题均已修正：浅色完成任务条白字对比度 4.87:1，辅助文字在选中底色上为 4.72:1，键盘焦点线在浅色表面上不低于 3.64:1。README 两张截图同步更新为隔离演示数据下的实际界面。

macOS 原生补验已完成：480px 清单标题栏、任务原位编辑、详情表单焦点、独立日历与七列日期／右侧抽屉、设置自定义主题选择，以及浅深主题跨窗口一致性均正常。补验发现标题失焦后被通用输入样式覆盖而出现边框，已提高标题选择器的明确性，保持标题在聚焦和失焦时均无边框；补充该状态断言后，相关 9 项端到端回归通过，独立复核确认修正。macOS 包已重新构建并校验签名，Windows AMD64 构建通过；未进行 Windows 原生 GUI 验收。

本次未调整数据模型与业务功能，未访问或修改用户正式任务数据。
