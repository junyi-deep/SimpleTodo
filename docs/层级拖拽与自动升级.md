# 层级拖拽与自动升级

对应 [issue #3](https://github.com/junyi-deep/SimpleTodo/issues/3)。本轮规则覆盖旧文档中的占位块、拖到空白处保持原父级、默认全部折叠及仅下载安装包的说明。

## 列表拖拽

- 使用一套 Pointer 拖动处理，不再同时启用浏览器原生 HTML 拖动，避免原生 WebView 取消后残留半透明状态。任务预览跟随指针；落点用带小圆点的蓝色细线表示。
- 水平每移动约 22px 调整一层投影，向左减少缩进，可将整个子分支提升到同级或拆为一级主任务；向右可嵌套。投影按完整子树高度限制在五层内。
- 拖到列表最顶部或最底部时，投影固定为一级主任务。开启“完成项置底”时，未完成任务的末尾落点位于已完成任务之前，线条和提交共同遵守此约束。
- 拆出分支保留任务 ID、完整后代、完成状态及原计划日期。拆出的主任务为普通任务，不复制原根的提醒或重复规则；原重复实例标记为例外，未来重复模板不变。
- 新增 `Promote` 事务：同时更新新旧根、后代 root_id、原父任务聚合状态和根顺序，检查快照修订及原根版本，并使用命令回执保证重试幂等。失败不留下半棵子树。
- 成功嵌套后自动展开目标路径；取消、Esc、失焦或结束拖动都清理线条与源行状态。仅未完成任务可拖动。

## 展开层级与自动延期

- 过滤图标与多选图标之间新增眼睛按钮，气泡中用滑条设置显示到第 1—5 层，默认两层。
- `expandDepth` 保存于 SQLite 设置表，重启后恢复；改变层级会重新应用展开范围，普通任务轮询不会覆盖本次手动折叠状态。只调整可见范围，不删除或改变任务层级。
- 未完成任务自动延期默认开启。已有用户明确保存的关闭选择保留；设置页在缺少该字段时也按开启显示。重复任务仍遵循自己的日期规则。

## 自动升级安装

- 关于页检查 GitHub 最新稳定版本，发现新版后可选择“升级并重启”，也保留“仅下载安装包”。使用当前已保存的更新代理。
- 升级前通过组件确认框说明重启及专注/提醒的短暂停止。确认后自动下载 ZIP；界面显示下载、校验及重启阶段。
- 两平台均核对 GitHub 发布资产提供的 SHA-256，限制解压路径、文件类型、数量和总大小。macOS 另外核对应用标识、内部版本、arm64 Mach-O 及代码签名完整性；Windows 核对 PE/amd64，不声称提供开发者证书签名或内部版本验证。
- 在目标所在目录准备新程序，先备份任务库，再启动由当前可执行文件复制的独立助手。助手通过 `--apply-update` 模式运行，等待原 PID 退出后同目录替换并启动新程序，不移动或覆盖任务数据目录。
- 替换或启动命令失败时恢复旧程序，并尝试重新启动旧版；结果写入独立的更新结果文件，后续启动可以显示失败原因。等待旧进程超时则保持原文件。无法自动启动时保留旧文件，供用户手动打开。
- 应用目录不可写、macOS 应用隔离位置、包校验失败等情况会报错并保留手动下载入口；不会申请管理员权限或绕过系统安全提示。若数据目录放在应用内部，先迁移数据再升级。

## 验证

- Playwright 65 项全部通过，新增 5 项专项覆盖默认两层及持久化、左右拖动及完整分支拆出、顶底一级/Esc 取消、升级确认/取消/失败重试，以及完成项置底下根排序和子树提升的投影与提交一致性。
- Go 全套测试与 go vet 通过。新增提升事务的日期/后代/幂等/失败回滚、无效安装包拒绝、安装替换、启动失败恢复、等待退出超时、两种替换失败后的旧版恢复启动断言。
- 前端类型检查、生产构建、Vitest 9 项通过；macOS arm64 生产 QA 构建及临时签名校验、Windows amd64 生产编译通过。
- 用真实签名 macOS ZIP 与 Windows PE ZIP 在临时目录验证准备、校验和原子替换，数据标记保持不变。另用复制出的真实可执行文件运行独立助手，验证等待父进程退出、模拟新版启动失败、恢复并启动旧夹具以及结果落盘。该夹具未启动 Windows GUI。
- macOS 480×720 隔离 QA 窗口验证默认两层、滑条改为三层并在重启后恢复、实际左拖子任务拆出一级主任务；只读 SQLite 核对完整后代及计划日期。未对用户安装的应用执行远端升级；Windows 原生 GUI 未实测。
- 独立复核提出的完成区投影与替换失败恢复启动两项问题已修复，限定这两项的复核结论为 ship。原生残留状态已通过统一指针路径修复并补验。

本地截图和测试日志保存在忽略的 `.impeccable/review/` 与临时目录；测试库、安装夹具和用户数据不提交到公共仓库。
